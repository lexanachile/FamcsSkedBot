# Настройки рыбалки

Единый серверный каталог: `catalog.ts`.

- `name`, `image`: подпись и URL фотографии во frontend.
- `phrases`: одна или несколько фраз. Сервер случайно выбирает одну за заброс.
- `drift`: потеря настоящего прогресса в секунду, диапазон клиента 0–1.
- `shake`: амплитуда декоративного движения в пунктах шкалы, 0–8.
- `shakeSpeed`: скорость декоративных рывков, 0.2–5.
- `spots`: `reeds`, `deep`.
- `periods`: `night`, `morning`, `day`, `evening`.
- `rain`: `null` — любая погода, `true` — дождь, `false` — без дождя.

POST `/api/fishing/cast` принимает `{ spot, period, rain }`. Ответ содержит
только случайный идентификатор встречи и силу/тряску текущей рыбы.
Одна выбранная карточка хранится в KV под отдельным `fishing:encounter:`
префиксом 10 минут. Данные расписания не меняются.
POST `/api/fishing/reveal` принимает `{ token }`, возвращает одну карточку
с одной фразой; раньше 9 секунд после заброса раскрытие недоступно.
Повторное раскрытие того же токена возвращает ту же фразу.

Каталог не отправляется в браузер. Это предотвращает чтение всех фраз
из frontend bundle, но не является античитом или полной защитой от
постепенного сбора ответов API. Dev-погоде сейчас доверяет сервер.
Для публичного рейтинга понадобятся авторизация и проверка игры на сервере.

Нужно опубликовать API вместе с frontend. Дополнительные секреты не нужны:
используется существующий KV binding. Локально запускайте Worker на 8787,
а frontend на 8080 — клиент выбирает локальный API автоматически.

Проверки: `node --test pkgs/worker-api/tests/fishing.test.mjs` из корня,
`npx tsc --noEmit` из `pkgs/worker-api`.
