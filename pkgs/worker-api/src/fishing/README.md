# Рыбалка и профиль Mini App

Настройка маршрута `/api/*`, WebSocket и порядок публикации описаны в
[инструкции Cloudflare](../../../../docs/cloudflare-request-optimization.md).

## Перед публикацией

Используется существующий DB -> schedule_db. Должны уже существовать таблицы,
созданные пользователем: miniapp_colors(telegram_id, revision, colors_json) и
fishing_players(telegram_id, username, revision, game_json, sync_json).
Код не создаёт и не удаляет таблицы.

В API Worker famcsschedulebot добавьте секрет TELEGRAM_BOT_TOKEN от бота,
который открывает Mini App. Он нужен именно API Worker, а не только webhook-боту.
Другие новые секреты не нужны. Токен не записывать в git, frontend или логи.

HTTP-запросы требуют Authorization: tma <Telegram.WebApp.initData>.
WebSocket передаёт initData первым сообщением; каждая команда затем проходит
те же проверки авторизации в общем обработчике. Авторизация не передаётся в URL.
HMAC и auth_date проверяются на сервере, срок входа — сутки, затем нужно
переоткрыть Mini App. ID из тела запроса не используется. Телефон и Telegram
Desktop под одной учётной записью используют один профиль. Обычный браузер
без Telegram-входа продолжает показывать расписание, но не сохраняет игру
на сервере. Отдельный браузерный Telegram Login пока не реализован.

## Хранение и API

Игра НИКОГДА не обращается к KV. GET profile создаёт одну строку при первом
входе, затем читает её; username обновляется только при изменении.
POST cast сохраняет заброс/расход прикормки, reveal сразу сохраняет улов в D1.
Встреча — зашифрованный AES-GCM
токен, ключ с разделением назначения выведен из секрета бота.
У пользователя один выбор награды на четырёхсекундный интервал: повторный
запрос не меняет рыбу и не позволяет повторно начислить тот же улов.
Reveal доступен через 2,5 секунды для обычной рыбки и 9 секунд для преподавателя;
токен заброса живёт около 10 минут.

POST sync принимает полный клиентский JSON и список зашифрованных квитанций.
JSON баланса не является доказательством: применяются только новые серверные
квитанции. game_json и sync_json меняются одним условным UPDATE по revision.
Конфликт приводит к повторному чтению/слиянию, не к потере второго пакета.
Повторный пакет не пишет строку повторно. Квитанции действуют сутки от начала
интервала; после этого сервер возвращает expired, и клиент сообщает о потере
неотправленного вовремя улова. Метки обработанных квитанций хранятся внутри
sync_json и очищаются при следующем новом начислении после истечения срока.
Максимум 200 квитанций на запрос, проверка размера тела до JSON parsing.

GET collection считает владельцев отдельно для каждой пары fish_id + phrase_id. У каждой открытой фразы свой owners и выборка usernames; закрытая фраза возвращает нулевую статистику.
GET leaderboard возвращает первые 50 мест и место текущего игрока по stats.totalCaught. Счётчик растёт на фактический размер обычного улова и на 31 за преподавателя (карточка и бонус 30 рыбок); покупки и выбор съесть/выпустить его не уменьшают.
Статистика владельцев считается одним SQL-запросом и кэшируется на четыре
минуты, рейтинг — на минуту. Параллельные запросы объединяются в одном isolate.
Это не глобальная гарантия одного чтения:
перезапуски и разные isolates делают собственные запросы. Персональные ответы
имеют Cache-Control: no-store. Возвращается выборка до пяти тегов.
Пользователь без тега входит в N. У закрытой карточки нет имени/фото.

GET/PUT /api/colors используют отдельную таблицу, revision и серверный savedAt.
PUT старой версии возвращает 409. Значения цветов и размер JSON валидируются.

## Награды и ограничения

catalog.ts — единственный каталог преподавателей. Базовый TEACHER_CHANCE = 0.04; удочки добавляют от 0 до 0.06, а каждый сохранённый обычный улов добавляет 0.01 к следующему шансу. Сохранённый редкий улов сбрасывает накопление.
После редкой поклёвки выбирается конкретная фраза по её `weight`: сначала среди ещё не открытых фраз, а после заполнения коллекции — среди всего каталога. У каждой фразы свой блок `fight` с настройками сложности skill check. Каталог отформатирован так, чтобы текст, вероятность и сложность каждой фразы редактировались рядом. Фразы Васьковского имеют минимальные веса и максимальную сложность.
Обычный улов начисляет 1–5 wallet.smallFish; преподаватель начисляет +1
fish[id].count и 30 рыбок. Преподаватели отбираются по deep и времени Минска.
Клиентские время/дождь не влияют на награду. Карточки с rain != null пока
исключены: серверный источник погоды ещё не подключён. Текущие карточки
имеют rain: null. Dev-время и дождь меняют внешний вид сцены.

Подписи защищают выдачу/повторное начисление, но НЕ доказывают прохождение
skill-check: результат мини-игры пока определяется клиентом. Это не защита
от автоматической игры.

GET /api/fishing/shop возвращает публичные цены и описания. POST shop/buy
одним условным UPDATE проверяет баланс, списывает рыбок и выдаёт предмет.
Необязательный requestId делает повтор покупки идемпотентным в течение суток:
он хранится в закрытом поле _purchases существующего game_json.
POST loadout выбирает только купленную удочку или имеющуюся прикормку.
Прикормка расходуется атомарно при первом забросе нового четырёхсекундного слота;
повтор запроса возвращает тот же результат и не списывает вторую порцию.
Dev-выбор удочки, прикормки и точного редкого улова влияет на сервер только для пользователя из
TEST_TELEGRAM_USER_ID и не расходует его предметы. `devFish` имеет вид `teacherId:phraseId`; допустимые значения сервер возвращает в `profile.devCatalog` только при включённых dev options. Выбранная пара гарантированно попадает в следующий заброс.

Квоты Cloudflare общие с ботом; создание таблиц не резервирует лимит.
Один пакет — один UPDATE строки; чтения/создание профиля считаются отдельно.
Публичный aggregate сканирует JSON профилей, его стоимость зависит от масштаба.

## Проверки

Из корня: node --test pkgs/worker-api/tests/fishing.test.mjs
Реальный локальный WebSocket: node --test pkgs/worker-api/tests/fishing-socket.test.mjs
Из pkgs/worker-api: npx tsc --noEmit

API-тесты используют настоящий SQLite in-memory с адаптером D1; KV подменён
объектом, который бросает ошибку при любом обращении. Это локальная проверка,
не подтверждение live D1, Cloudflare deployment или Telegram WebView.
