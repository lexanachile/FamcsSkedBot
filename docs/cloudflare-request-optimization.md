# Настройка экономии запросов Cloudflare

## Что изменено

- Версия ресурсов сайта: `v=83`, включая вложенные импорты.
- На `famcs.online` все API-запросы идут на `/api/*` того же домена. На localhost API остаётся `127.0.0.1:8787`, на preview-доменах используется прежний `workers.dev`.
- Рыбалка открывает один WebSocket `/api/fishing/socket`. Через него идут существующие игровые команды; Hono вызывает обработчики внутри процесса, без сетевого запроса к другому Worker. Авторизация передаётся первым сообщением, не в URL.
- Если WebSocket не установился за пять секунд, используется HTTP; следующая попытка WebSocket не раньше пяти минут. Уже отправленные команды автоматически через HTTP не повторяются. После разрыва следующее действие создаёт соединение заново.
- При скрытии игры/вкладки соединение закрывается после ответа на текущую команду; на сервере неактивное соединение закрывается через пять минут. Heartbeat-опроса нет.
- Улов сохраняется сразу на сервере. IndexedDB хранит восстановление неподтверждённого раскрытия; повторное раскрытие не начисляет награду повторно.
- Покупка получает `requestId`, сохраняемый на устройстве до ответа. Повтор той же покупки после потерянного ответа возвращает состояние без второго списания. Старые HTTP-клиенты могут работать без этого дополнительного поля.
- Цвета проверяются раз в десять минут в видимой вкладке вне игры, при возвращении к расписанию/фокусе — если последняя проверка старше минуты. Правки отправляются через три секунды. Ошибки приводят к увеличению интервала повторов до пяти минут.
- Профиль не перечитывается сразу после свежего игрового ответа; одновременные обновления объединяются. Магазин кэшируется десять минут, коллекция и рейтинг — минуту. Новый редкий улов или изменение коллекции в профиле сбрасывает её кэш.
- Статистика владельцев считается одним SQL-запросом и кэшируется на четыре минуты в каждом Worker isolate; с клиентским кэшем задержка может достигать пяти минут. Рейтинг кэшируется на минуту на сервере и клиенте: до двух минут задержки. Личный баланс и покупка подтверждаются немедленно.
- Первое CAS-обновление использует уже прочитанную строку игрока; при конфликте версия перечитывается. Убрано повторное чтение D1 на обычном пути cast/reveal/buy/loadout.

Новые таблицы, SQL-миграции, KV namespaces, Durable Objects и секреты не нужны. Используются текущие `DB` и `TELEGRAM_BOT_TOKEN`. Расписание остаётся в KV.

## Публикация: сначала API, затем сайт

1. В Cloudflare убедитесь, что зона **famcs.online** находится в том же аккаунте, что Worker **famcsschedulebot**. DNS-запись сайта должна быть проксируемой через Cloudflare (оранжевое облако). Существующую привязку домена к Pages сохраняйте.
2. В терминале из корня проекта:

   ```powershell
   cd C:\About\Projects\FamcsSkedBot\pkgs\worker-api
   npx tsc --noEmit
   npx wrangler deploy
   ```

   `wrangler.toml` уже содержит:

   ```toml
   workers_dev = true
   routes = [{ pattern = "famcs.online/api/*", zone_name = "famcs.online" }]
   ```

   Wrangler должен опубликовать код и маршрут. Если используете API token, ему нужны права на публикацию Workers и изменение Worker Routes в зоне `famcs.online`. При отсутствии прав настройте их или используйте авторизованный `npx wrangler login`.

3. В **Workers & Pages → famcsschedulebot → Settings → Domains & Routes** проверьте маршрут `famcs.online/api/*`. Если он не был создан, добавьте Worker Route для зоны `famcs.online`. Это **Route с путём**, а не Custom Domain на весь сайт. Шаблон `famcs.online/*` здесь использовать не нужно: статику продолжает отдавать Pages.
4. Проверьте маршрут до публикации фронтенда:

   ```powershell
   curl.exe -i https://famcs.online/api/fishing/profile
   curl.exe -i https://famcs.online/api/fishing/socket
   ```

   Без Telegram авторизации первый адрес должен вернуть JSON с HTTP **401**, второй без Upgrade — JSON с HTTP **426**. HTML главной страницы означает, что запрос попал в SPA fallback Pages и маршрут API ещё не работает. Не публикуйте новый фронтенд до исправления маршрута.
5. Опубликуйте изменения репозитория в ветку, которую собирает Pages, обычным для проекта способом. Дождитесь успешного deployment проекта **famcs-schedule**. Новый `index.html` должен ссылаться на `app.js?v=83`. Проверьте именно build/deployment в Cloudflare; локальные проверки сайт не публикуют.
6. Переоткройте Mini App в Telegram. Дополнительные настройки Telegram BotFather и новые секреты не требуются.

Если уже задан Content Security Policy, `connect-src` должен разрешать `https://famcs.online` и `wss://famcs.online` (а также используемые внешние сервисы погоды). В текущем коде отдельного запрета WebSocket не добавляется.

## Проверка после публикации

- В Network при запуске рыбалки должно быть соединение `wss://famcs.online/api/fishing/socket` со статусом **101**. `profile`, `cast`, `reveal`, магазин и рейтинг видны как сообщения внутри этого соединения. Отдельные HTTP-запросы допустимы в резервном режиме.
- Сделайте несколько успешных забросов, покупку, смену снасти; проверьте баланс после переоткрытия Mini App и на другом устройстве под тем же Telegram аккаунтом.
- Отключите и восстановите сеть во время раскрытия улова. Повтор должен восстановить результат без повторного начисления. Повтор покупки с неподтверждённым ответом должен списать цену один раз.
- Сверните и верните Telegram на iPhone/Android. Проверьте восстановление игры и соединения. При простое в игре не должно быть ежеминутных запросов `/api/colors`.
- В Workers Metrics сравните Requests и Errors за сопоставимые интервалы. Отдельно проверьте D1 Rows read/written и ошибки CPU. WebSocket экономит входящие запросы Worker, но не отменяет операции D1 и ограничения CPU.
- Если WebSocket стабильно переходит на HTTP, проверьте Upgrade 101, ошибки Worker и доступность `wss` в конкретной сети/WebView. Секреты и Telegram initData в логи не копируйте.

## Локальные проверки

```powershell
node --test pkgs/frontend/tests/*.test.mjs pkgs/worker-api/tests/fishing.test.mjs
node --test pkgs/worker-api/tests/fishing-socket.test.mjs
node --check pkgs/frontend/app.js
cd pkgs/worker-api
npx tsc --noEmit
```

WebSocket-тест использует Miniflare/workerd и временную локальную D1, не production. В Windows runtime может требовать запуск вне песочницы. Отклонённые Upgrade проверяются отдельно через Hono: Miniflare 3 оставляет необработанное соединение для `unexpected-response` при неуспешном Upgrade.

## Откат

Для полного отката сначала верните предыдущий deployment Pages, использующий `workers.dev`, затем предыдущую версию API. Схема D1 не менялась; неизвестные внутренние поля JSON не затрагивают старый интерфейс. Маршрут `/api/*` можно оставить. При откате API до версии без WebSocket клиент автоматически перейдёт на HTTP, если маршрут `/api/*` продолжает вести к API.
